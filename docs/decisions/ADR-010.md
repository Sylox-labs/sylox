# ADR-010: Signal dispute ruling deadline and default outcome

Status: Accepted, feat/staking · Date: October 8, 2026

## Context

`dispute_signals` opens a signal dispute and locks the disputer's bond; `resolve_signal_dispute` lets the committee rule on it. Before this round nothing bounded how long a dispute could sit open: a slow, absent or captured committee could leave an epoch's endpoint `Disputed` forever, with the disputer's bond locked and the keeper's own stake left exposed to an unresolved accusation, indefinitely (GitHub issue #4, carried over from spec v1.2's review). This is the same structural gap ADR-002 closed for event disputes; signal disputes had no equivalent.

## Decision

- New parameter `signal_dispute_ruling_secs` (default 7 days, `SIGNAL_DISPUTE_RULING_SECS` in `contracts/risk-oracle/src/lib.rs`), counted from `dispute_signals`, not from the original posting's own `pending_until` dispute window (a different clock: how long the COMMITTEE may take to rule, not how long a keeper's posting stays open to a NEW dispute).
- `DisputeRecord` gains `opened_at`, set once at `dispute_signals` time.
- If the committee has not ruled by `opened_at + signal_dispute_ruling_secs`, anyone can call `resolve_signal_dispute_timeout(asset, epoch)`:
  - Default outcome mirrors ADR-002's rule for data backed claims: the keeper's posting already happened and went unchallenged by a timely ruling, so it stands (slot `Final`, the same state a `keeper_wins: true` committee ruling produces).
  - The disputer's bond (the only `BondKey::SignalDispute` lock that exists; `RiskOracle` never locks a bond for a keeper's own posting, Section 24.2) is released in full via `release_bond`, never `forfeit_bond`. The keeper's stake is left untouched: no `slash` call. Neither party is penalized for the committee's own silence.
  - A miss is recorded against the committee address read fresh from `Governor.committee()` at resolution time, the same `CommitteeMisses`-style bookkeeping ADR-002 established for event ruling timeouts, grounds for rotating the committee through governance.
- `resolve_signal_dispute_timeout` is permissionless and callable exactly once per dispute: `clear_dispute` runs in the same call, so a second call (whether before or after a timeout, or after a committee ruling that arrived first) finds no open dispute and returns `DisputeWindowClosed`, the same code `dispute_signals`/`resolve_signal_dispute` already use for "no open dispute here."

## Consequences

- No signal dispute can leave an epoch `Disputed`, a disputer's bond locked, or a keeper's posting un-finalized for longer than `signal_dispute_ruling_secs` past the dispute, independent of whether the committee ever acts.
- `resolve_signal_dispute_timeout` is the second and only other `RiskOracle` change this PR makes (`feat/staking`'s task brief named it as the one allowed change; `dispute_signals` passing its disputed epoch's poster through to `Staking.lock_bond` as the new `subject` parameter, needed so `remove_keeper` can withhold a keeper's bond release while a dispute against its postings is still open, was approved as a second, narrowly scoped addition during review — see the PR's "Spec deviations" section).
- New API `resolve_signal_dispute_timeout`, new event `signal_dispute_timed_out`, new error `RulingDeadlineNotReached` (112), new storage `DisputeRecord.opened_at` and `CommitteeMisses(committee)` (mirroring ADR-002's key shape exactly, so a future dashboard or governance check can read both contracts' miss counters the same way).
- Sections touched: technical-doc.md 5.4, 7.8, 12.1 (new function), 13 (new event), 14 (new error), 15.1 (new storage), 23 (new parameter); `contracts/risk-oracle` `storage::DisputeRecord`; `contracts/types` `BondKey` unaffected (no new variant, only `Staking.lock_bond`'s own signature gained `subject: Option<Address>`, documented alongside this ADR in the PR rather than as its own ADR, since it is a plumbing change to an existing call, not a new policy decision).
