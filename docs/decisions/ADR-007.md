# ADR-007: Event topic convention

Status: Accepted, spec v1.2 · Date: October 8, 2026

## Context

Section 13 specified every event's topics as `("sylox", <contract>, <event>, <primary key>)`, four topics. `soroban-sdk 29.0.0`'s `#[contractevent]` macro panics at compile time (`LengthExceedsMax`) for more than 2 custom prefix topics, because `stellar-xdr`'s `ScSpecEventV0.prefix_topics` is declared `SCSymbol prefixTopics<2>` in the XDR schema: a hard limit, not a bug or a version quirk to work around. Discovered while building `RiskOracle` (spec v1.1, PR #2): the four-topic convention cannot be emitted literally by any contract using this SDK version, so every event-emitting contract would have hit the same wall independently.

The emitting contract's own address is already attached to every Soroban event outside its topics (the `contract_id` field every `ContractEvent` carries), so a topic that only says "which contract" is redundant with data `getEvents` already returns for free.

## Decision

Every event's topics are `("sylox", <event_name>, <primary key>)`, three topics: `"sylox"` and the event's own name (e.g. `"signals_posted"`, `"band_changed"`) as the two custom prefix topics the XDR schema allows, followed by the event's primary key field as the one `#[topic]`-marked data field. The event's own name was the first topic consumed to make room; it moves to the second topic instead of being dropped, since `getEvents`'s own filtering model matches topics positionally and an event's name is exactly what an integrator filters on.

This fits the 2-prefix-topic limit for every contract in the system, not only `RiskOracle`. It is the one topic convention every Sylox contract must use going forward; Section 13 is amended to match the convention actually implemented, not the literal four-topic text.

## Consequences

- Every event in Section 13's table drops its contract name from the topic tuple; the `Contract` column stays for documentation and the error-code-style range-per-contract convention, but it is no longer part of the emitted topics.
- An indexer or SDK client filters `getEvents` on `("sylox", <event_name>)` to get exactly one event type across every contract, rather than needing the contract address and an event name both.
- No change to any event's data fields or its primary key topic; only the two prefix topics change.
- Sections touched: technical-doc.md 13; every contract's event definitions (confirmed so far: `RiskOracle`; the others have not yet been built against this convention and must follow it when they are).
