# ADR-002: Ruling deadline and default outcome

Status: Accepted, spec v1.1 · Date: October 8, 2026

## Context

In v1.0 an escalated event waited for the committee with no time limit. A slow, absent or captured committee could leave an event Escalated forever, which kept every series it might cover in Pending and kept sellers' collateral locked indefinitely. A challenger could also stall a valid Tier 1 event simply by challenging it.

## Decision

- Each event definition carries `ruling_deadline_secs` (default 14 days), counted from escalation. In v1 a challenge escalates in the same call, so the clock always starts at the challenge.
- If the committee has not ruled by the deadline, anyone can call `resolve_timeout(event_id)`:
  - Escalated Tier 1 events (Depeg, IssuerFreeze), where the data already met the definition: default **Declared**. The challenger carries the burden of proof.
  - Tier 2 and Tier 3 events, which rest on claims: default **Rejected**. MintWithoutBacking, whose Tier 1 data is only a flag that needs committee confirmation, is treated as a claim: default Rejected.
- On timeout every bond on the event is refunded. Nobody is slashed for the committee's silence.
- Missed deadlines are recorded per committee address and are grounds for rotating the committee through governance.
- `EventRecord` gains `escalated_at`; the deadline is `escalated_at + ruling_deadline_secs`.

## Consequences

- No series can sit in Pending beyond the ruling deadline plus one challenge window after its post expiry acceptance period (ADR-003); for the default Depeg definition that is at most 18 days after expiry.
- `resolve_timeout` is permissionless, so the bound does not depend on the committee acting.
- A challenger can no longer block a valid Tier 1 event by stalling: the default favours the data.
- The committee's performance becomes measurable onchain (`committee_misses`).
- New API `resolve_timeout`, new event `ruling_timed_out`, new errors `RulingDeadlinePassed` and `RulingDeadlineNotReached`, new storage `CommitteeMisses(committee)`; the separate `escalate` call is removed.
- Sections touched: technical-doc.md 4.3, 8 (state diagram), 8.1, 8.9 (new), 12.2, 13, 14, 15.1, 22.4, 22.5, 23; `contracts/types` `EventDefinition.ruling_deadline_secs`, `EventRecord.escalated_at`.
